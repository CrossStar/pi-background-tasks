# Persistent local runtime

## Remote SSH bridge

`remote-bridge.mjs` is a plain Node executable for Linux. Each SSH exec sends one JSON object on stdin (at most 1 MiB, followed by EOF) and receives one JSON envelope: `{ok:true,result}` or `{ok:false,error:{message,taskId?}}`. The bridge exits after flushing its response and has a 20-second deadline. SSH authenticates the user; callers do not supply IPC tokens. Supervisor capabilities are removed from returned records.

The request is `{method,params}` with required object `params` (use `{}` for `ensure`). `method` is `ensure`, `start`, `get`, `list`, `cancel`, or `logs`; operation arguments below belong in `params`. `ensure` starts the existing detached daemon and checks its handshake. Its result includes `pid`, `startToken`, `protocol: "pi-background-tasks-remote"`, `version: 1` (bridge wire protocol), `daemonProtocolVersion: 1` (the shared IPC protocol used), `runtime: {node,platform,arch}`, and `serviceRoot`. These protocol constants describe the deployed bridge; the daemon handshake independently advertises `sessionOwnership`, which the bridge propagates and verifies for scoped requests. Clients must reject unsupported bridge protocol versions. `start` also ensures availability, accepts `id`, absolute `cwd`, `name`, `command`, optional `description`, `ownerSession`, `notifyOnCompletion`, `triggerOnCompletion`, `timeoutSeconds` (default 0), and `maxOutputBytes` (default 20 MiB). Only the daemon launches supervisors. Commands use remote `/bin/bash -c` and the remote bridge process environment; request-supplied shell/environment fields are ignored. Retry with the same task ID after any lost response; start errors include `taskId` because admission may already exist. No local fallback or automatic command replay occurs.

`get`, `cancel`, and `logs` take `id` and optional `ownerSession`; `list` also accepts `ownerSession`. `list` accepts optional absolute `cwd` and numeric `offset` and returns the daemon's bounded page `{records,diagnostics,nextOffset}`; filtering does not change the pagination cursor. `logs` accepts byte `offset` (default 0) and `maxBytes` (1–49152, default 49152). It reads only the validated stored output file and returns `{data,nextOffset,eof,size}` with base64 bytes. Offsets are byte positions, including within UTF-8 sequences; EOF describes the current file snapshot, not task completion. Caller paths are never used.

Deploy the bridge and its sibling runtime modules together in an immutable private version-hash directory via sydney-kit. Keep `PI_BG_SERVICE_DIR` stable across deployments (default `~/.pi/background-tasks-remote`). The bridge sets this default before dynamically importing `shared.mjs`, so its root singleton cannot capture the local-runtime default. An explicit environment override is supported for isolated tests. `list` returns raw pages; the Sydney client assembles its TaskList. Shared IPC owns authentication. An incompatible handshake or protocol error fails closed; this bridge does not upgrade or kill an existing daemon. Handshake validation checks the current protocol's PID and identity fields; future protocol revisions must preserve compatibility or explicitly reject requests. Run the local SSH-transport stand-in test with `node --test tests/persistent/remote-bridge.test.mjs`; no live SSH host is required.


The client exports `ensureService()`, `start(StartRequest)`, `get(id, ownerSession?)`, `list(cwd?, ownerSession?)`, and `cancel(id, ownerSession?)`. A supplied selector must be a nonempty string. The daemon checks exact owner equality before get, cancel, or bridge log reads, and filters list pages before returning records. Missing legacy owners never match a selector and are never implicitly bound. Scoped corrupt-admission diagnostics contain only generic information; known other owners are excluded. Pagination uses raw admission offsets, including empty filtered pages. The client independently validates returned record ownership. Repeated start requires identical owner metadata (including absence), before consulting a supervisor; ownership is immutable.

Daemon ping and bridge ensure advertise the actual `sessionOwnership: 1` capability. Scoped requests require that capability even though wire protocol version remains 1. Older daemons fail explicitly; clients never kill them or replay tasks to upgrade. Operators must arrange a daemon-only restart retaining supervisors and the service directory; running supervisors continue and remain accessible after restart. Internal supervisor capability RPCs are unchanged. Calls without selectors remain the raw per-user API for low-level tooling. Session ownership is application isolation, not an OS security boundary: the same OS user can access the files.

`createClient({root})` fixes a client's service directory; module-level functions resolve current configuration on every call. Start requests supply shell, args, env, timeoutSeconds, maxOutputBytes and optional windowsVerbatimArguments. Retry ambiguous responses with the same id. Records expose outputFile, outputBytes, metadata, timestamps and terminal exit information. The metadata file is record.json beside outputFile. Client validation rejects malformed record fields and output paths.

A durable admission and an exclusive supervisor launch claim prevent replay, including a crash between claim and spawn. Commands are never restarted after reboot. Environment travels through authenticated IPC and supervisor stdin and is not recorded. Supervisors own output, process groups and terminal writes; output fsync precedes atomic terminal replacement and POSIX parent directory fsync. Output I/O failures initiate cancellation and record failure where storage permits. Storage failure can prevent a terminal record; no success is inferred in that case.

An unavailable supervisor makes get throw SUPERVISOR_UNREACHABLE. Consumers must preserve their last running snapshot. Unreachability alone never changes a durable status. List returns stored snapshots through bounded pages. Its array result has a diagnostics property containing {id,message} entries for missing or corrupt admission records; healthy records, including completed records, remain available. Stored running admissions carry an unverified diagnostic until get successfully reaches their supervisor. Cancellation is bounded and records unknown failure when tree termination cannot be verified. POSIX cancellation retains ownership of the original process group across leader exit and pipe closure. A single TERM/KILL escalation remains scheduled until the group disappears or the bounded verification deadline expires. Observing ESRCH permanently releases group ownership; natural completion never sends a kill. Surviving or unverifiable groups after escalation produce unknown rather than a false killed claim. Windows uses an absolute system taskkill path with bounded capture and timeout; helper failure produces unknown. No PID-only adoption occurs.

The root is PI_BG_SERVICE_DIR or ~/.pi/background-tasks. POSIX directories use 0700 and files 0600. Private random authentication tokens determine unpredictable endpoints. Linux abstract Unix sockets provide kernel single-instance arbitration without stale pathname unlink. Only Linux crash recovery is in the release scope; macOS and other Unix platforms require operator recovery of stale pathname sockets and are not claimed to support automatic daemon crash recovery. Windows uses named pipes with application authentication; filesystem ACL protection must be supplied by the user's root directory. Client-to-daemon, bridge-to-daemon, daemon-to-supervisor, and supervisor-to-shell spawns set `windowsHide: true` while preserving their existing detached, stdio, shell, and unref behavior. Verify cold service startup and warm task startup with the updated runtime; a resident daemon can retain older spawn code across extension reloads. Use an isolated service root for verification, or confirm no active tasks before restarting an existing service. No explicit pipe ACL guarantee is claimed. Linux is the tested platform.

Standalone processes are plain mjs without a transpiler dependency. Completed records and claims remain indefinitely. Registry and extension integration are separate. Tests use handshake daemon identity, actual processes, daemon SIGKILL/restart, duplicate admissions and direct duplicate-supervisor rejection.
